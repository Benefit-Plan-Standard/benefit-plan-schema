# Governance

The **Benefit Plan Standard** strives to be a transparent, community‑driven initiative.  
The schema and supporting materials are maintained under an open governance model inspired by other successful data standards (e.g., FHIR, OpenAPI).

## Principles

1. **Vendor neutrality** – The standard is not tied to any particular carrier, technology vendor, or commercial product.
2. **Openness** – All discussions, proposals, and decisions are conducted in public and documented in this repository.
3. **Consensus** – Schema changes require review and agreement by a representative set of stakeholders, including carriers, benefit administrators, and independent technologists.
4. **Versioning and stability** – Changes follow semantic versioning.  Major version increments introduce breaking changes; minor versions add backward‑compatible extensions; patch versions clarify or fix issues without functional impact.

## Process

### Proposals

1. Anyone may open an issue or pull request proposing a change or addition to the schema.  
2. Proposals should include a rationale, use cases, and examples.  
3. Proposals will be labeled for discussion and assigned to a community reviewer.

### Review

1. After a period of open discussion, the maintainers will call for consensus.  
2. If consensus is reached, the proposal will be merged into the next draft version.  
3. If consensus is not reached, the proposal may be deferred for further exploration.

### Releases

1. Draft versions are published for community testing and feedback.  
2. Final releases require successful implementation and validation by at least two independent adopters.  
3. Release notes summarize changes and provide migration guidance.
