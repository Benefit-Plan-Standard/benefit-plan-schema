# Medical MVP crosswalk to the SBC InsurancePlan profile

Diego Orofino, the Benefit Plan Standard, dorofino@benefitplanstandard.org. A draft for the workgroup, not a workgroup decision.

The [Benefit Plan Standard](https://benefitplanstandard.org) is an open JSON format for health plan benefits, published under the MIT license. Its schema, the importers that read CMS public files, the converter to FHIR and the example plans live in [one repository](https://github.com/Benefit-Plan-Standard/benefit-plan-schema). This document is the crosswalk to the SBC InsurancePlan profile, version 0.2, dated October 20, 2026, 1 of 3 documents that make up the medical MVP technical specification for the CMS Health Tech Ecosystem Real-Time Benefits workgroup. The other 2 are the [technical specification](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/README.md) and the [data dictionary](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/data-dictionary.md). All 3 are in the [repository folder](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/tree/main/docs/specs/rtb-medical-mvp), and the files they name are in the [repository](https://github.com/Benefit-Plan-Standard/benefit-plan-schema). This document is published as `carin-crosswalk.md` in that folder; a Word copy carries the same content.

This crosswalk maps each item of the medical MVP [data dictionary](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/data-dictionary.md) to the SBC InsurancePlan profile in the CARIN Digital Insurance Card implementation guide, package `hl7.fhir.us.insurance-card#2.0.0-ballot`. SBC stands for Summary of Benefits and Coverage. For each item it says where the value lands in the Bundle that the Benefit Plan Standard repository's [`scripts/to-insuranceplan.js`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/scripts/to-insuranceplan.js) writes from a Benefit Plan Standard document, and gives 1 of 3 verdicts. The assignments follow the workgroup's medical MVP scope (Monica Chopra's pledge proposal, October 2026).

The crosswalk to the SBC InsurancePlan profile is a Part B item in the workgroup's GA draft, the document "RTB Medical. What payers would be asked to supply for GA" (Monica Chopra, October 2026, a draft for discussion, not a workgroup decision), not a GA ask. The SBC InsurancePlan profile is at ballot. This crosswalk exists so a pledgee can produce the Bundle when the SBC InsurancePlan profile publishes, and nothing in the MVP's SHALL list depends on it.

The whole profile is ballot-stage. The SBC InsurancePlan profile, its extensions and the code systems it binds are draft and experimental in that package ([converter specification](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/insuranceplan-converter.md) section 2, in the Benefit Plan Standard repository). 3 changes to the SBC InsurancePlan profile were proposed from Benefit Plan Standard implementation experience and merged in June 2026: multi-tier cost sharing (FHIR-57525), deductible applicability (FHIR-57526) and structured benefit limitation (FHIR-57527). They are in the STU2 ballot of September 2026, not in a published release, and each row they apply to names them.

The crosswalk is generated from the Benefit Plan Standard repository by [`scripts/build-rtb-crosswalk.js`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/scripts/build-rtb-crosswalk.js) from [`shall-should.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/shall-should.json) and [`carin-mapping.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/carin-mapping.json) in the same repository folder and [`fhir/carin-sbc-crosswalk.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/fhir/carin-sbc-crosswalk.json) (38 canonical keys mapped to the SBC InsurancePlan profile's benefit categories), all in the Benefit Plan Standard repository. The item names and field paths are the [data dictionary](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/data-dictionary.md)'s, so the 2 files list the same rows in the same order. To change it, change those files and run the generator again.

## How to read it

- **aligned**. The value lands in a profile element with the same meaning and no loss; converter specification section 6 maps it directly.
- **different**. The value reaches the Bundle, but in a Benefit Plan Standard extension, as text only, or with a loss that converter specification section 7 names. The note says which.
- **not covered**. The Bundle does not carry the item. The note says why. The verdict adds "no element" when the SBC InsurancePlan profile has no element for the item and the Benefit Plan Standard converter ([`scripts/to-insuranceplan.js`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/scripts/to-insuranceplan.js)) emits nothing, and "gap" when the item is a known gap (G1 to G8), so there is nothing to map yet. A gap is work on the 2 importers, listed in the [README](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/README.md) with the other known gaps, and the note says what travels today.
- A row that applies to 1 program names the program in the Verdict cell. Where the 2 programs get different verdicts, the cell gives both, the same way the [data dictionary](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/data-dictionary.md) splits field paths.
- The SBC InsurancePlan element is a FHIR path inside `InsurancePlan`. When the value travels in an extension, the cell gives the extension's URL. "None today" means the Bundle has nothing for the item.
- A benefit is placed in `coverage.benefit` and `plan.specificCost.benefit` only when its canonical key is in `fhir/carin-sbc-crosswalk.json`, and only placed benefits have `cost` entries. Any other benefit is listed by identity in `bps-unmapped-benefit` (converter specification section 8.3).
- Marketplace Bundles are written with `--excluded-services`, as in the [README](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/README.md)'s commands.
- "Read from" names the sections of the Benefit Plan Standard converter specification, `docs/specs/insuranceplan-converter.md`, that state the mapping, and any other file the verdict is read from.
