# Medical MVP data dictionary

Diego Orofino, the Benefit Plan Standard, dorofino@benefitplanstandard.org. A draft for the workgroup, not a workgroup decision.

The [Benefit Plan Standard](https://benefitplanstandard.org) is an open JSON format for health plan benefits, published under the MIT license. Its schema, the importers that read CMS public files, the converter to FHIR and the example plans live in [one repository](https://github.com/Benefit-Plan-Standard/benefit-plan-schema). This document is the data dictionary, version 0.3.6, dated October 27, 2026, 1 of 3 documents that make up the medical MVP technical specification for the CMS Health Tech Ecosystem Real-Time Benefits workgroup. The other 2 are the [technical specification](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/README.md) and the [crosswalk to the SBC InsurancePlan profile](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/carin-crosswalk.md). All 3 are in the [repository folder](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/tree/main/docs/specs/rtb-medical-mvp), and the files they name are in the [repository](https://github.com/Benefit-Plan-Standard/benefit-plan-schema). This document is published as `data-dictionary.md` in that folder; a Word copy with the same content is sent with the specification and is not in the repository.

The terms the 3 documents use, such as SSA county code, Section A, PBP benefit category, tier row, accumulator, slot, excerpt and STU2, are defined at the top of the [README](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/README.md), the technical specification.

This data dictionary lists each item in the medical MVP scope and where it is in a Benefit Plan Standard document written by the 2 public-file importers in the Benefit Plan Standard repository. The Medicare Advantage importer ([`scripts/from-pbp.js`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/scripts/from-pbp.js)) reads the CMS Plan Benefit Package (PBP) Benefits files for contract year 2027. The Marketplace importer ([`scripts/from-marketplace-puf.js`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/scripts/from-marketplace-puf.js)) reads the CMS Health Insurance Exchange public use files (PUFs) for plan year 2026. The assignments follow the workgroup's medical MVP scope (Monica Chopra's pledge proposal, October 2026). The service and benefit names are the scope's suggested names. Every other sentence in this dictionary was written for the Benefit Plan Standard and is not the workgroup's wording.

The dictionary is generated from the Benefit Plan Standard repository by [`scripts/build-rtb-dictionary.js`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/scripts/build-rtb-dictionary.js) from [`shall-should.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/docs/specs/rtb-medical-mvp/shall-should.json) in the same repository folder, [`fhir/pbp-crosswalk.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/fhir/pbp-crosswalk.json) (41 rows, 35 with a canonical key), [`fhir/marketplace-puf-crosswalk.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/fhir/marketplace-puf-crosswalk.json) (273 benefit names, 84 mapped) and [`vocabularies/canonical-benefits.json`](https://github.com/Benefit-Plan-Standard/benefit-plan-schema/blob/main/vocabularies/canonical-benefits.json) (version 1.4.0, 124 keys), all in the Benefit Plan Standard repository. To change it, change those files and run the generator again.

## How to read it

- **SHALL**. Required for the MVP. A pledgee makes the item available to the member on request, wherever it applies to the member's plan.
- **SHOULD**. Optional for the MVP. It may become SHALL at GA.
- **KEY**. The identifier an app uses to find the plan's document. Not an item shown to the member.
- Each program column gives the label, then the CMS file and the columns the Medicare Advantage importer or the Marketplace importer reads for the item.
- A field path says where the value is in the document. `benefits[canonical_key=primary_care]` is the item of `benefits` whose `canonical_key` is `primary_care`, and `[tier_id=IN]` works the same way; `[]` means every item and `[0]` the first. Documents of both programs follow Benefit Plan Standard schema 1.2.0.
- "Quoted verbatim in `source_references`" means the CMS file has the value but the Benefit Plan Standard schema has no field for it, so the 2 importers copy the column name and the value into a `source_references` excerpt.
- "Not on the Medicare Advantage list" or "Not on the Marketplace list" means the scope does not ask for the item in that program. Where a crosswalk still maps the key, the cell names the rows.
- "Not in the CMS file" in a note means the files the Medicare Advantage importer or the Marketplace importer reads cannot carry the item for that program; the note says what that importer writes instead.
- "(not read)" marks a column that is in the CMS file but that the Medicare Advantage importer or the Marketplace importer does not read today.

How the Medicare Advantage importer reads the files:

- Each service category has its own columns in its own file, 1 row per plan. A Medicare-covered category is covered on every plan; when both its copay and coinsurance answers are No, the Medicare Advantage importer writes a $0 copay step and quotes both answers.
- Minimum and maximum columns become a range (`amount_min` and `amount_max`, `rate_min` and `rate_max`) when they differ.
- Every tier row quotes, in its notes, the cells it was read from.

How the Marketplace importer reads the files:

- Every benefit is a row of `benefits-and-cost-sharing-puf.csv` with the same columns, found by its exact `BenefitName` and the plan's `PlanId`.
- Costs are text, such as "$30.00" or "20.00% Coinsurance after deductible". The Marketplace importer reads each string into a copay or coinsurance step and quotes both strings in the tier's notes.
- `IsCovered` applies to the whole benefit, so every tier row of a benefit carries the same covered value.

## Not in the CMS file

Medicare Advantage:

- Coverage dates. No PBP file has a date column. The Medicare Advantage importer writes `plan_year` only.
- Cost in the second in-network tier. The PBP files have no second in-network tier. They carry facility cost tiers for inpatient and skilled nursing stays only, which the Medicare Advantage importer writes as `cost_designation` tiers such as `IN_1A_TIER_1` and `IN_2_TIER_1`.

Marketplace:

- Monthly plan premium. Neither file the Marketplace importer reads has a premium column; premiums vary by age and area and are in the Rate PUF, which the Marketplace importer does not read. The Marketplace importer writes no premium.
- The extra benefits, cost and details. The Benefits and Cost Sharing PUF has no column for whether a benefit is included or an optional add-on, and none for authorization or referral, so these rows carry neither.
- Over-the-counter allowance. No `BenefitName` in the plan year 2026 file is for this benefit; the crosswalk lists all of the file's names.
- Rides to medical appointments. No `BenefitName` in the plan year 2026 file is for this benefit; the crosswalk lists all of the file's names.
- Meals. No `BenefitName` in the plan year 2026 file is for this benefit; the crosswalk lists all of the file's names.
